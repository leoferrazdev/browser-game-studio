# Public Source Map

The public core is based on an operational workflow developed from browser-game production, QA, and multiplatform release practice. Private project histories and vault paths are intentionally excluded.

| Area | Reusable principle | Revalidation |
| --- | --- | --- |
| Game production | Reach gameplay quickly, explain the first action, provide feedback, progression, and a reason to return | Review after major workflow changes |
| Build architecture | Keep one game core and produce versioned, auditable packages per platform | Review when the build pipeline changes |
| Platform release | Keep SDKs, ads, metadata, media, and checklist state inside platform profiles | Recheck official portal documentation before every submission |
| Evidence | Separate local tests from portal QA, review, publication, and player metrics | Required for every release |
| AI assistance | Agents must understand the goal, make bounded changes, test, document, and report limitations | Review when agent tooling changes |
